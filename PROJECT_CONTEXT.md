# ПИКС — контекст проекта

Живой файл: вайб, решения, договорённости и находки. Обновляется по ходу работы.

---

## Что это

**ПИКС** — образовательный ресурс для студентов СПО. Первая дисциплина —
гражданское право, курс Полины. Механика одна и та же для любой дисциплины:

```
конспект → игра-проверка → 80% и выше → следующая тема открыта → шер-карточка
```

Тема запирается, пока не сдана предыдущая. Карточка с результатом уходит
в сторис — это и есть мотивация доучиться до конца.

---

## ПИКСФЛОУ — как контент попадает на сайт

1. Тема из учебного плана + методички → Claude собирает **полноразмерную PDF-лекцию**,
   которую Полина читает на паре.
2. Из той же PDF → **презентация** к паре.
3. Из той же PDF → **краткий конспект на ПИКС**; сама PDF ложится в правую колонку
   конспекта, чтобы студент скачал одним нажатием.
4. К теме генерируется **игра**. Сдал на 80%+ — открылась следующая тема.
5. В конце игры — **шер-карточка**: скинуть преподавателю, показать группе.

Пункты 3–5 работают на сайте уже сейчас. Пункты 1–2 и загрузка PDF — этап 4.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Бэкенд | Supabase + Vercel | Postgres, авторизация и хранилище из коробки; хватает бесплатного тарифа |
| Вход | Имя + пароль, без почты | Имя занимается навсегда; забыл пароль — сбрасывает преподаватель |
| Порог сдачи | 4 из 5 = 80% | Совпадает с требованием и с дизайном игры |
| Тема | Один светлый режим | Хендофф не предусматривает тёмной; переключатель убран |
| UI-киты | Не используем | Tailwind/shadcn дают ровно тот генеративный вид, которого проект избегает |

## Дизайн

Источник истины — `design_handoff_piks` (хендофф из Claude Design). Всё
воспроизведено попиксельно: значения, кривые, длительности.

**Подложка** `#F7F6F3`, текст `#14140F`, карточки белые. Гарнитура одна —
**Unbounded** 300–700, заголовки 500, абзацы 300.

**Палитра тем** — `src/design/palette.ts`. 16 тем получают тон по дуге
бирюза → синий → сирень → розовый: `hue = 178 + i * 10.5`. Светлота и
насыщенность одинаковы у всех, поэтому ряд корешков читается как один объект.
У каждой темы пять заливок: `color` (плоская), `grad` (объёмная, у выбранной),
`holo` (голограмма кнопок и карточки), `matte` (запертая), `deep` (обводки).

**Голограмма** всегда идёт с `background-size: 360%` и анимацией `holoFlow`.
Параллакс на корешке и шер-карточке считается от положения указателя: карточка
наклоняется, радужный слой и блик едут против неё.

## Как устроен код

```
src/
  design/palette.ts   ← тон темы, пять заливок
  content/            ← books.ts (16 тем), quiz.ts (банк вопросов), subjects.ts, types.ts
  lib/
    layout.ts         ← все размеры двух раскладок + хук ширины окна
    progress.ts       ← прогресс и гейтинг; здесь же точка замены на API
    shareCard.ts      ← рендер карточки 1080×1350 на canvas
    format.ts         ← pad, склонения
  components/         ← Header, TopicChip, Blocks, ShareCard
  pages/              ← Home, Shelf, Reader, Quiz, Result, Games, Progress
  styles/             ← tokens.css, base.css, interactions.css
```

**Роутинг.** `/` — выбор дисциплины, `/s/:subjectId` — полка,
`/s/:subjectId/:slug` — конспект, `.../quiz` — игра, `.../result` — результат,
`/games`, `/me`. Дисциплина в пути: вторая появится без правок вёрстки.

**Проверка знаний.** В `src/content/quiz.ts` лежит банк вопросов на тему (сейчас
по 14 у каждой из трёх готовых). На попытку `buildAttempt()` собирает случайные
10 вопросов и перемешивает варианты внутри каждого: порядок не выучить,
пересдача даёт другой набор. Порог — 80% верных, `passMark()` считает его от
размера попытки, а не от зашитой пятёрки.

**Гейтинг — один источник на все экраны** (`src/lib/progress.ts`):

```ts
prevGate(i)   // последняя тема ДО i, у которой есть конспект
isUnlocked(i) // gate < 0 || passed[books[gate].slug] !== undefined
```

Цепочка идёт по темам с конспектом: тема без конспекта не запирает следующую
навсегда. `passed` пополняется только при score ≥ 4.

## Что дальше

**Этап 2 — Supabase.** Таблицы `students(id, name_key, name, pass_hash, group_id)`,
`attempts(student_id, slug, score, at)`, `questions`. Проверка ответов уезжает
на сервер: сейчас `correct` виден в DevTools. Плюс админка Полины: сброс пароля,
журнал группы.

**Этап 3 — форматы игр.** Сейчас одна викторина, но уже на банке вопросов.
Планируются карточки на переворот, сопоставление «ситуация → статья», сортировка
по порядку действий, «верно/неверно» на скорость. Плюс режим «игра плюс» —
тренировка без гейтинга, открывается после сдачи основной.

**Этап 4 — ПИКСФЛОУ целиком.** Генерация PDF-лекции и презентации, загрузка PDF
в хранилище, ссылка в правой колонке конспекта.

**Мелочи в очереди:** настоящий QR вместо плейсхолдера на полке; серверный рендер
OG-картинки для ссылки на результат.

## Журнал находок

**React стирает `backgroundImage`, если рядом лежит `background: undefined`.**
Для `undefined` React делает `style.background = ""`, а это shorthand — сбрасывает
всё семейство, включая уже выставленный `backgroundImage` и `backgroundSize`.
Голограмма пропадала с кнопок и полосы прогресса. Правило: в одном объекте стилей
не смешивать shorthand `background` с longhand `backgroundImage` — только longhand
плюс `backgroundColor`.

**`margin: 0 auto` в flex-колонке отменяет растяжение.** Горизонтальные auto-поля
снимают `align-self: stretch`, элемент сжимается до содержимого и уезжает к центру.
Заголовок «Игры» съехал на 150px. Лечится явным `width: 100%`.

**Фиксированная высота игрового поля промахивается.** `calc(100vh - 220px)`
подобрано под заголовок в одну строку; на двухстрочной подписи кольцо уезжало под
нижний край. Поле должно брать остаток экрана флексом, а не вычитать угаданное число.

**На телефоне панель выбранной темы обязана идти НАД рядом корешков.** Шестнадцать
корешков по 52px — это 900px: при выборе темы панель оказывается за экраном и
кажется, что нажатие ничего не сделало. На десктопе порядок из хендоффа сохранён.

**Стартовые координаты плиток ставятся при инициализации, а не в первом кадре rAF.**
В фоновой вкладке кадры троттлятся, и плитки стоят стопкой в углу.

**`navigate()` в теле рендера даёт белый экран.** Ранний выход вида
`if (!данные) { navigate(...); return null; }` обновляет роутер во время отрисовки:
компонент возвращает null, редирект не доезжает, URL остаётся прежним — студент
видит пустую страницу. Правильно — вернуть `<Navigate to={...} replace />`.

**Белый экран не должен быть возможен в принципе.** Любая ошибка рендера теперь
ловится `ErrorBoundary` и превращается в понятный экран с кнопкой «К темам»;
boundary пересоздаётся по `key={pathname}`, иначе после ошибки все следующие
переходы остаются сломанными.

**Формат хранения прогресса меняется — нужна миграция.** Прежние записи были
просто числом (счёт из пяти), стали `{score, total}`. Без миграции у студента
с уже пройденной темой в строке результата появлялось `undefined/undefined`.
